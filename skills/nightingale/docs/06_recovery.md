# 收工与恢复

> 说明怎么停机、崩溃后怎么续、失败边界在哪。核心承诺：**任何失败都不阻塞心跳**；退出的是执行单元，不是夜莺。

## 一、收工（用户喊停）

- 用户直接杀进程或关页面即可；恢复时用 `claude --resume` 等回到对话查看运行情况。
- **次日人工审查清单**：
  1. `git log` 演化叙事（项目目录内）。
  2. 产出物位置。
  3. 失败清单与待办。
  4. 逐条过一遍运行期间的**危险操作**（删除/覆盖等，本应在启动时界定边界）。
- 危险操作未经人工确认前，执行单元不应擅自做。

## 二、恢复（崩溃后重启）

1. 重启后先读 `state/system_state.json`，找到最后一致状态。
2. 检查 `queue/` 中哪些任务状态为 `running` 但实际已死 → 标为 `interrupted`。
3. 从最近检查点继续（检查点 = 已落盘的状态 + 已提交的 commit）。

## 三、失败边界

| 对象 | 策略 |
|---|---|
| workflow（开发者/评估者）失败 | 重试最多 N=3 次；仍败 → 任务标 `failed` → 继续下一个 |
| Loop 心跳超时/卡死 | 由 Watchdog 干预（NUDGE → KILL+RESTART，占位待启用） |
| 单轮派发失败 | 跳过本轮，下轮心跳重试，不阻塞 |

## 四、安全边界（运行期）

- 空间边界：只碰独立小项目，不碰主线仓库与重要数据。
- 时间边界：只跑到次日人工审查为止。
- 失败边界：搞砸了最多浪费一个晚上。
- 审计边界：每一步变化都有 git commit + 日志记录。
