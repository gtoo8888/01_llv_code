## 4. 代码红线

这些是几轮 review 后定下来的，**改之前先读第 6 节的理由**：

1. **core 不认识公司**。出现公司名、“保险责任”“方案一”就是放错层。
2. **公司差异写在 adapter**：`dims` / `split_blocks` / `thresholds` / `pages` / `min_column_rows`。
3. **不要为一家公司改全局默认**。默认服务多数，例外写在该公司的 `Spec(...)` 里。
4. **守卫常量不进 `Spec`**：`MIN_TEXT_CHARS`、`MIN_NUMBERS_PER_PAGE`、`MAX_AGE`，失败就 fail，不允许 adapter 关掉。
5. **文本 IO 只走 `parse_utils`**：显式 UTF-8、`newline="\n"`；不写裸 `read_text()` / `open()`。
6. **不留死字段、死分支**。这轮删过 `Spec.extra`、`Spec.age_columns`、`if reason and rows`、版本号。
7. **新增公司 = `index.json` 一行 + `companies/xxx.py` 一个文件**。CLI 会校验两边一一对应，缺哪边都报错。

## 6. 关键设计决策（别急着推翻）

| 决策 | 原因 |
|---|---|
| 按公司写 adapter，不做通用 profile | 复用单位是“公司”，同公司跨年变化小；profile 的 JSON schema 会蠕变成一门语言 |
| 删除 `Spec.age_columns` | 它用的是“过滤后”的列号，每页列数不同，实测少解析 2,478 行且不报错 |
| 切块逻辑搬进 `picclife.py` | 只在人保一份 PDF 上验证过，放 core 会被误认为通用；core 只保留 `split_blocks` 这个回调 |
| `min_column_rows` 默认回到 5 | 之前为太保降到 2，等于用一家特例污染全局；现在太保自己声明 2 |
| 阈值收进 `Thresholds` | 判定门限散落在函数里无法从 adapter 调；但守卫常量除外 |
| 不做 OCR | 现有语料都有文字层；无文字层直接失败，不猜 |
| 不做结果缓存 | 缓存键漏掉 adapter / core 规则时会静默返回旧结果；本项目规则改动远多于 PDF 改动，缓存是负收益。跑多久都接受 |

## 7. 已知问题与技术债（按优先级）

| 优先级 | 问题 | 影响 | 建议 |
|---|---|---|---|
| 高 | **没有任何自动化测试** | 回归全靠抽样断言 + 人工 | 至少给 `core.build_rows` / `is_age_sequence` / `find_terms` 写合成数据的单测 |
| 中 | 新华缺 0 岁 | 年龄 1–65，少一行 | 允许年龄格带文字（如 `0（须出生满30日）`）再提取数字 |
| 中 | 人保 p4 上半（58–62 岁尾块）被阈值挡掉 | 可能少 5 个年龄 | 对照原文确认是否与 p3 重复 |
| 中 | 阳光 60 岁男性 5 年交为空 | 可能是产品规则，也可能列映射错 | 人工看一眼原文 |
| 低 | `find_terms` 里 `8 / -4 / 10` 仍是硬编码 | 表头合并不好调 | 等真出问题再进 `Spec` |
| 低 | `column_tolerance` 是绝对点数 | 大版面可能偏紧；国寿恰好没超 | 若再遇到大版面失败，改成按字号比例 |
| 低 | `expected_rows` 无人使用 | 行数断言能力闲置 | 给每份 adapter 补一个预期行数 |
